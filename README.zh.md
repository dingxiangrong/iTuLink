# iTuLink 统一范式工程仓库
> 六部五道体系 · 五大仓库｜第四层：工程落地仓库
> 顶层架构基准文档：101.iTuLink 总体架构 R1.0.4

## 仓库定位
将【未来范式仓库(ECO)】输出的AI生态理论，落地为可部署、可执行、可共建的智能系统工程范式与技术规范。
承接六部体系**【运部】**全部落地实践职责，实现完整正向链路：
**哲学理论 → 准科学模型 → 产业研判 → 未来生态范式 → iTuLink工程实现**

> 宪法级约束：`101.iTuLink 总体架构 R1.0.4` 为本仓库顶层宪法文档，定义全部核心组件、角色权责与拓扑约束；102、103下级规约必须遵从101，不可篡改组件权责与拓扑。

## 核心命题
- 真正AI生态不是工具堆砌，必须沉淀为一套开发者共同遵循的**统一工程行为范式**。
- 生态不靠平台强制垄断，依靠范式带来的效率优势吸引参与者自发共建。
- 内核机制 **KBCC 信息采矿机制**：以实践为源、采掘为手段、知识为沉淀，为生态持续供给运转活水。
- 架构制衡原则：认知层、调度路由层、业务执行层严格解耦，禁止顶层组件越权直连，通过SV端侧自治域完成中转，实现安全与权责隔离。

## 核心组件总览（来自101总体架构）
|组件缩写|组件全称|简要作用|
|---|---|---|
|SE|主权入口 Sovereign Entry|主权人机唯一顶层入口，采集输入、渲染现象，无业务与推演逻辑|
|PT|枢接口 Port|隶属于SV，收敛SE外部接入流量，多协议适配|
|SV|端侧自治域 Sovereign Vessel|局域路由中继、能力注册治理、指令准入校验、客观现象归一收拢|
|UPP|单元业务平台 Unit Product Platform|业务域总控，身份、会话、权限管理，CC能力注册发布源头|
|CC|能力容器 Capability Container|自治能力载体，承载各类业务与硬件能力，执行后产出客观现象|
|CDT|认知推演树 Cognition-Deduction-Tree|全局任务规划内核，认知推演、任务拆解，输出结构化意图指令|
|SAM|主权聚合记忆 Sovereign Aggregate Memory|CDT旁路记忆载体，沉淀时序记忆，维持人格连续性，被动读写|

> 架构铁则：跨顶层组件交互必须经由SV中转；同UPP域内CC之间允许业务直连。CDT/SAM不直接操控SE/UPP/CC。

## 核心职责
1. **顶层范式标准化**
落地五道一法中**系统之道**，维护101宪法总体架构，迭代102/103下层规约；完整定义SE/PT/SV/UPP/CC/CDT/SAM组件权责、拓扑约束、元语规范，强制架构制衡。

2. **构件与参考实现输出**
输出iTuLink统一SDK、组件框架（WebCC、DeviceCC、MCPCC、SpringCC等）、工程样例；提供各组件最小可运行参考原型。

3. **KBCC信息采矿机制工程化**
实现从人群-AI持续实践活动采掘知识的工程链路，沉淀生态资产；KBCC作为特殊CC纳入整体组件体系参与调度流转。

4. **范式迁移与垂直域适配**
面向不同垂直行业做业务域适配，支撑开发者侧工程生态、用户侧人-AI垂直共生生态落地生长。

5. **工程产物送检闭环**
所有架构实现、原型、业务适配方案提交至 **AI-FPA归因仓库**，执行工程排障、逻辑审证、公理自洽检验；遵循A31归因四律完成归因回流。
