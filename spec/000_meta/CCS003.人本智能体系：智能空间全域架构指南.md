# 003.人本智能体系 · 智能空间全域架构指南
**认知—能力 连接规范 | CCS：Cognition Capability Specification**

> 定位说明：
> 本架构不是某一款软件，不是单一应用，也不是普通应用开发模式。
> 它是人借助科技拓展自身边界的下一代人本智能技术体系范式。
> 科技作为人的能力外延；拓界主体为人。各类业务、运维、设备、知识、通讯能力，都是依托本体系之上的派生产物。体系定义人如何通过技术向外延伸感知、行动，厘定人与机器之间的主权、授权、流转、执行契约。
>
> 本架构的核心使命：
> - **SV（端侧自治域）完成智能空间的连接与主权边界管控**
> - **CDT（认知推演树）与 SAM（主权聚合记忆）共同完成私脑的工程落地**
>
> 二者协同，使“私脑”从哲学概念转化为可部署、可校验、可收回的自治单元。

## 一、架构核心总纲
本架构重构传统 Agent、Skill 工具调用范式。

传统范式：把 AI 当作独立增强应用；
本范式：以人作为主权本体，整套技术体系为人服务，作为人的外延载体，实现人自身能力拓界。

### 四大底层公理（永久锁死）
1. **主权归人，AI 受权执行**：人类持有体系最终决策权；AI 无原生自主权，仅接收人类主权授予的有限自主权，在授权边界内推演、执行。科技是人的能力外延，不能替代人的主体地位。

2. **思行彻底解耦**：私脑只思，CC 只行。认知层不触碰资源，执行层不产生推理。思考与执行分离，保障人可以在任意环节介入、干预、叫停。

3. **技术可复用、语义强隔离**：底层技术组件可以共用；上层架构角色、层级、主权、职责严格区分，不因底层技术同源而合并实体。

4. **能力全部容器化**：全域业务、系统、主机、设备、知识、通讯能力，统一封装为 CC 容器，具备标准化执行闭环。人向外拓展的每一类能力，均可管控、可校验、可收回。

### 全域标准五层架构（自上而下不可逆）
**SE 主权入口层 → Port 全域接入层 → SV 端侧自治域层 → 私脑（CDT&SAM）认知推演层 → 智能空间 CC 容器集群执行层**
配套底座：SAM 主权聚合记忆

> 层级不可逆约束释义：上层实体可以向下发起调用、下发事件；下层实体禁止主动向上发起调用。结果回传、事件上报属于应答回流，不属于下层主动调用上层，应答回流路径强制原路返回。缓存推演结果仅允许 SV 做透传缓存，禁止 SV 主动触发私脑开展推演，规避越层越权。

> 允许上行通道白名单（不可逆规则例外集合）
> 本白名单为全集，不在此清单内的上行行为一律禁止。
> 1. 任务应答回流：下层收到上层请求之后，原路返回对应应答报文（包含正常结果、业务异常、业务报错）。
> 2. 事件上报回流：由上层下发指令触发派生事件，沿原链路向上回传事件。
> 3. SV 透传缓存：SV 仅做报文透传缓存，不主动发起对私脑的调用，不产生新推演。
> 4. 错误告警上报：CC 执行过程产生业务故障、运行异常，只能作为对应任务上下文附属载荷向上回流，CC 不可独立主动发起全新上行请求。
> 5. 存活心跳上报：组件存活状态、保活心跳，仅允许上报至 SV，不允许直接穿透至私脑、SE 主权层；由 SV 统一汇总向上透传。
> 6. 授权被动感知回调：授权变更、授权过期信号，由 SV 向下推送通知至 CC；CC 只做本地状态变更，CC 不主动向上轮询 / 查询 SE 授权状态。

## 二、SE 主权入口层（全域最高层级）
### 核心定义
人本智能体系唯一最高主权域，代表人的本体。
整套体系是人向外拓界的延伸，一切意志起点归于人。
- 人类为全部决策的最终裁定方
- AI 一切自主权、执行权限，全部由 SE 授权产出
- 交互的起点、终点、否决权、终止权归属于 SE

### 核心权责
授权、收权、干预、驳回、终止、观测、感知。
人通过授权，将自身意志投射进技术体系，依托科技，拓展人自身感知与行动边界。

## 三、Port 全域接入层（人机唯一通道）
### 核心铁律
Port 归属 SE 主权层，不属于任何 CC，不属于执行层。
Port 唯一职责：外部世界异构信号 - 内部统一元语报文归一转换。
现实世界各类通路，经由 Port 完成归一，是人进出智能空间的触点。

### 全域标准 Port
1. Web-Port：浏览器用户接入
2. PC-Port：本地终端主机用户接入
3. Com-Port：全域通讯媒介接入（企微 / 短信 / 邮件 / IM 入站）

### 关键架构隔离
- Com-Port：人进来（主权接入通道）
- Com-CC：系统向外执行（人向外拓界的执行能力）
底层技术可以同源，架构语义分层彻底隔离。

## 四、SV 端侧自治域（全域唯一中枢）
全域路由、调度、报文封装、授权透传的唯一核心总线。
承接 SE 侧主权上下文，完成全域寻址分发。

**核心能力：**
1. chat-event 统一事件元语驱动
2. path 路径寻址 + event_type 枚举精准路由
3. Envelope/Payload 信封载荷二分标准报文
4. mid_instruct /fin_instruct 双阶指令分发
5. 全域 CC 注册、发现、隔离、调度
6. 授权上下文全域透传、边界校验

## 五、私脑（CDT）认知推演层（私有认知外延）
> 命名释义：私脑，私有之私。属于归属人的私有认知外延，服务于当前主体，不共享、不对外开放。
> 全域唯一认知生产单元，是人的认知外延。
> 负责目标拆解、路径推演、任务规划，产出标准化结构化指令。
> - 只做推演、拆解、推理、规划；
> - 不接入外部资源、不持久存储、不直接操作业务与硬件；
> - 在人类授予的自主权边界内开展推演；超出授权范围，强制回交 SE 做人类终审。

## 六、智能空间 CC 容器集群（全域执行层，可落地实体）
### CC 统一标准范式（全部容器遵守）
1. 标准化自治能力容器
2. Task 任务生命周期
3. Action动作项(AC)定义
4. prepare → check → submit 三阶执行闭环
5. 全部执行权限来源于 SE 主权授权

### CC 两大分类
1. 业务应用类 CC：面向上层业务逻辑
2. 系统设备类 CC：面向主机系统、硬件、运维管控

#### （一）业务应用类 CC
##### 1. Spring-CC｜服务端业务应用容器
- 运行域：后端服务应用层
- 管理对象：企业业务、业务 Service、数据库业务数据、表单流程、业务审批
- 约束：仅处理业务语义，不触碰服务器系统命令、硬件资源

##### 2. Web-CC｜浏览器业务应用容器
- 运行域：浏览器 Web 沙盒
- 管理对象：前端页面组件、Web 业务交互、前端应用能力
- 约束：只承载上层 Web 业务，不操作系统底层权限

##### 3. KB-CC｜知识库业务容器
- 运行域：全域通用
- 管理对象：知识分类、文档管理、权限检索、知识闭环
- 隔离规则：底层存储技术可与 SAM 复用，语义严格隔离
- SAM：属于人的主权记忆；KB-CC：公共客体知识

##### 4. Com-CC｜全域通讯业务容器
- 运行域：全域通用
- 管理对象：系统对外推送、消息投递、邮件 / 短信 / 企微外发
- 隔离规则：入站消息走 Com-Port；出站执行走 Com-CC

#### （二）系统设备类 CC
> 归类逻辑：
> Host 系列：通用计算机主机，命令体系同源；
> Device-CC：非通用主机，异构外设、嵌入式硬件。

##### 1. Host-CC｜通用主机系统容器
- 覆盖对象：Linux 服务器、Windows 服务器各类业务主机
- 管理能力：系统命令、进程、磁盘运维、资源监控、主机文件
- 区分：Spring-CC 运行主机之上的业务；Host-CC 管理主机本身系统。

##### 2. PC-CC｜用户本地终端主机容器
- 覆盖对象：笔记本、台式机用户本地终端
- 管理能力：本地文件、本机命令、终端脚本、个人主机资源
- 归属 Host 同源体系，面向用户侧终端形态

##### 3. Device-CC｜异构外设硬件容器
- 覆盖对象：嵌入式设备、IoT、传感器、外接非标硬件
- 特征：设备异构、协议各不相同，不属于通用计算机主机

## 七、SAM 主权聚合记忆底座
- 归属：SE 人本主权私有底座
- 存储内容：用户人格、会话轨迹、个体偏好、长期行为记忆
- 架构铁律：**SAM 存「人」；KB-CC 存「物」。**

## 八、全域标准运行闭环（可落地执行流程）
1. 人类 SE 设定授权边界
2. 外部信号经由 Port 归一转换为内部元语报文，送入 SV
3. SV 携带授权上下文交付私脑（CDT）开展认知推演
4. 私脑产出标准化 instruct 指令；SV 依据 path 路由分发至对应 CC
- 业务诉求 → 业务应用类 CC
- 主机运维操作 → Host-CC / PC-CC
- 硬件设备操控 → Device-CC
5. CC 执行 prepare-check-submit 完整闭环，校验权限与执行结果
6. 执行产生的客观现象原路回传，经由 Port 反馈至 SE 人类主权入口

> 报文信封载荷、授权上下文、path/event_type、指令字段。
