## 102.3.1.1 架构描述

### 定位

本小节为元语架构总述，定义 Endpoint（通信端点）作为体系所有逻辑通信单元的公共基类。UPP、S1、SV 等全部业务逻辑角色，均派生自 Endpoint。
Endpoint 不是业务数据载体，是具备完整报文收发、元语调用能力的逻辑对象；业务数据仅承载于报文 payload，与 Endpoint 本身解耦隔离。

### Endpoint 基础属性

crid：Endpoint 实例全局唯一通信标识，为本端点的寻址地址。实例创建阶段按统一规则生成，实例全生命周期固定不变。
内置元语方法：call /post/notify /return/emit /forward/on，全部为 Endpoint 的实例方法，所有派生角色自动继承。

### 元语调用模型

所有元语方法，以 call 为例：
call (destEp: Endpoint, path: PathExpr, payload: Payload, ctrlMap?: CtrlMap) -> ResMsg

this：当前发起调用的 Endpoint 实例，this.crid 自动作为报文 meta 内 src_crid（源端点地址）。
destEp：目标通信端点对象，从 destEp.crid 提取值，自动填入报文 meta 的 dest_crid（目标端点地址）。
业务代码仅传入 destEp 对象，不直接读写 src_crid、dest_crid 字符串；元语层内部自动完成 meta 字段填充。

### Meta 报文基础结构（统一增加 src_crid /dest_crid）

```
{
   "meta": {
     "primitive": "call",
     "src_crid": "CRID-XXXX",
     "dest_crid": "CRID-YYYY",
     "path": "<接口路径>",
     "version": "1.0"
   }
}
```

### 双向回包规则

请求报文：src_crid = 发起端点 crid；dest_crid = 目标端点 crid。
应答 / 回执报文：远端 Endpoint 收到请求报文，读取入站 meta 的 src_crid，作为应答报文的 dest_crid；应答报文 src_crid 填充为当前远端 Endpoint 自身 crid。
依靠 meta 内自带源、目标双地址，天然支撑请求 - 应答双向路由，无需额外保存外部会话上下文用于回包寻址。

### 代理一体化约定

SV 部署在本地自治域，本质是壳，**不具备独立身份，不占用 crid 坑位**。SV 存在的目的，是让远端 CDT 在本地自治域内 "有一个可投递的地址"。
本地自治域路由映射：**SV 注册所用 crid 即 CDT 的 crid**。本地域内所有端点（例如 SE）寻址 CDT 时，dest_crid 填写 CDT 的 crid，报文路由投递至 SV。
SV 收到报文后，不执行业务逻辑、不消费 payload，使用 forward 元语做身份保留透传：报文原始 src_crid 保持不变，依旧携带上游发起端点（SE/CC）的 crid，转发至远端自治域内真实的 CDT 实体；CDT 可凭借原始 src_crid 完成鉴权、全链路追踪与个性化推演。
CDT 无法直接与本地自治域内其他端点建立通信，CDT 所有出站报文必须回传 SV。SV 收到 CDT 返回报文后，调用 notify、return 元语向上游回送结果；该阶段报文 src_crid 为 CDT 的 crid（即 SV 注册所用 crid），dest_crid 取自原始请求记录，投递至上游端点。上游端点依靠关联标识匹配请求，业务层对两段式代理链路保持透明。
SV 全程无自身身份，不修改报文 payload；forward 阶段保留原始 src_crid 语义，回送阶段 src_crid 统一为 CDT 的 crid（即 SV 注册所用 crid）。

### 约束

crid 全局唯一，同一体系内不存在两个 Endpoint 拥有相同 crid。
Endpoint 派生单元（UPP/S1/SV 等）可扩展自身专属属性与业务逻辑，但不可覆盖基类内置元语的基础路由行为。
ctrlMap 仅承载链路控制参数（deadline 等），不承载 dest 寻址目标信息；寻址目标由传入的 destEp 实例提供。
