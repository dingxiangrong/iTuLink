### 102.3.2.1 call（接口方法元语｜同步点对点查询）

**元语签名**：call(destEp: Endpoint, path: PathExpr, payload: Payload, ctrlMap?: CtrlMap) -> ResMsg

**描述**：call（接口方法元语｜同步点对点查询）。call 为体系同步定向交互通道，用于向单一指定对等 Endpoint 发起请求并阻塞等待应答。call 天然承载配对语义：发起调用 → 对等端处理完成，发送 return 元语作为应答，调用方拿到 return 报文结果后方可继续后续流程。适用于读取类、查询类、枚举类请求；写入、变更、执行类操作不得使用 call。

**元语层组包规则**：元语层自动完成消息组包，生成 meta、header 两段；业务侧传入 destEp 对象、path、payload、ctrlMap，无需手动填充 meta、header 字段。meta 内 `src_crid` 由元语层读取当前调用 Endpoint 实例`this.crid`自动填充；meta 内 `dest_crid` 由元语层从入参 destEp 对象提取填充。
**补充**：

1. call 请求报文与配套 return 应答报文，共用同一个 correlation_id，用于元语层完成请求应答配对。
2. header 新增 `deadline`，代表请求返回有效截止时间；`deadline = 0` 代表不限制超时。`deadline` 值由 ctrlMap 内配置项映射填充。

**请求报文（call）**：

```
{
  "meta": {
    "primitive": "call",
    "src_crid": "string",
    "dest_crid": "string",
    "path": "<由具体接口定义>",
    "version": "1.0"
  },
  "header": {
    "msg_id": "string",
    "correlation_id": "string",
    "timestamp": "long",
    "deadline": "long"
  },
  "payload": {
    "<业务参数由具体 path 定义>"
  }
}
```

**响应报文（return）**：

```
{
  "meta": {
    "primitive": "return",
    "src_crid": "string",
    "dest_crid": "string",
    "path": "<复用请求的path>",
    "version": "1.0"
  },
  "header": {
    "msg_id": "string",
    "correlation_id": "string",
    "timestamp": "long",
    "ret_code": "string",
    "ret_msg": "string"
  },
  "payload": {
    "biz_code": "0",
    "biz_msg": "",
    "data": { ... }
  }
}
```

**约束**：
header.ret_code/ret_msg：框架系统码，承载报文通信、解析、路由、链路层面的成功或失败。
**meta 字段定义**：

- primitive：元语原语类型，请求固定为 `"call"`，应答固定为 `"return"`。
- src_crid：本条报文发送端点 CRID。call 请求 src_crid 等于发起调用的 Endpoint 实例`this.crid`；return 应答 src_crid 等于处理请求的远端 Endpoint 自身 CRID。该字段由元语层自动填充，业务侧无需传入。
- dest_crid：本条报文投递目标端点 CRID。**dest_crid + path 组合准确定位目标 Endpoint 内部的目标方法**；EventBus 依靠 dest_crid 完成消息投递寻址。call 请求报文的 dest_crid 为被调用 Endpoint；return 应答报文 dest_crid 取自入站 call 请求 meta.src_crid（原始请求发起实体）。该字段由元语层自动填充，业务侧无需传入。
- path：接口路径表达式，return 应答报文复用 call 请求 path。
- version：元语协议版本。
**header 字段定义**：
- msg_id：本条消息实例唯一标识，每条消息独立生成。
- correlation_id：call 请求与配套 return 应答报文使用完全相同的 correlation_id，用于元语层完成请求应答配对。由 call 调用的元语层在构造请求时生成。
- timestamp：报文生成时间戳。
- deadline：请求返回有效截止时间，单位统一为毫秒；值为 0 表示无超时限制。该字段由入参 ctrlMap 映射生成，元语层读取并写入 call 请求报文 header；return 应答报文不携带 deadline。
payload 固定结构约定：所有 return 应答 payload 必须包含 biz_code、biz_msg，字段名称固定，不可改名。
- biz_code = "0"：业务执行成功，biz_msg 可为空字符串或省略；
- biz_code ≠ "0"：业务执行失败，biz_msg 存放可读业务错误描述；调用方识别到非 0 biz_code，直接忽略 payload.data 内容。
- biz_code 枚举值由各 path 所属模块文档自行定义，元语层不约束具体取值；
- 当 header.ret_code ≠ "0000" 时，biz_code /biz_msg 不可信，调用方禁止依赖该组字段。
payload.data：承载业务主体载荷，内部结构由具体 path 接口文档定义。业务失败场景下 data 建议置 null，由各 path 接口按需说明。
入站 call 请求报文抵达对等 Endpoint，首先进入该模块 on (事件报文) 统一入口，识别元语类型后路由至对应业务处理函数；业务处理完成，业务侧构造 return 元语报文作为应答。远端处理逻辑需校验 header.deadline，若当前时间已超过 deadline，直接构造 return 报文返回链路超时错误。
发起调用方收到的 return 应答报文直接交付本次 call 调用点，不进入发起方 on 入口。调用方元语层同样校验 deadline，超时直接抛出链路异常，丢弃远端后续到达的 return 应答报文。
return 应答报文 header.correlation_id 原样复制 call 请求报文的 correlation_id；应答报文生成独立新 msg_id。
return 应答报文 meta.src_crid = 远端处理端点自身 CRID；return 应答报文 meta.dest_crid = call 请求报文 meta.src_crid；应答报文 meta.path 原样复制请求报文 meta.path。
call 为点对点同步交互，不做一对多广播。
单 call 会话仅允许返回一次 return 应答，不支持多次推送；分段进度推送场景选用 post+notify+return。

> ctrlMap 说明：CtrlMap 为控制参数字典，承载链路控制类配置，`deadline` 是其中一项配置项；后续可在 ctrlMap 扩展其他控制参数，元语层自动映射至报文 header。
