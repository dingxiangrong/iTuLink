### 102.3.2.2 post（接口方法元语｜有来有回｜异步定向投递）

**元语签名**：post(destEp: Endpoint, path: PathExpr, payload: Payload, ctrlMap?: CtrlMap) -> ResMsg

**描述**：post 为点对点交互通道，用于向单一指定对等模块下发请求、推送任务事件。post 调用本地底层传输层方法提交报文；底层受理投递任务成功后，**元语层在本地内存构造 primitive=on 的就绪确认报文对象**。该对象不是远端回传的网络报文，仅用于统一上层返回报文结构。on 报文仅代表底层受理投递任务、投递通路就绪；不代表目标模块已经收到报文，更不代表业务开始执行。报文送达目标模块的时间不可预期，可能存在长时间延迟。业务中间分片、任务输出、收尾结果，全部作为后续事件送入预先注册的 on 处理器回调。适配 AI 多步推演、长任务、实时流式输出场景。post 支持 1 个或多个业务事件输出，每个事件报文都自带 meta。

**元语层组包规则**：元语层自动完成消息组包，生成 meta、header 两段；业务侧传入 destEp 对象、path、payload，可选传入 ctrlMap，无需手动填充 meta、header 字段。meta 内 src_crid 由元语层读取当前调用 Endpoint 实例 this.crid 自动填充；meta 内 dest_crid 由元语层从入参 destEp 对象提取填充。

**补充**：
post 请求报文、on 就绪报文、后续全部事件报文共用同一个 correlation_id，用于关联本次请求。
header 新增 deadline，表示请求返回有效截止时间；deadline = 0 表示不限制超时。deadline 值由 ctrlMap 内配置项映射填充；ctrlMap 不传时，deadline 默认等于 0。

**请求报文（post）**：

```
{
  "meta": {
    "primitive": "post",
    "src_crid": "string",
    "dest_crid": "string",
    "path": "<由具体接口定义>",
    "version": "1.0"
  },
  "header": {
    "msg_id": "string",
    "correlation_id": "string",
    "timestamp": "long",
    "deadline": "long"
  },
  "payload": {
    "<业务参数由具体 path 定义>"
  }
}
```

**本地构造就绪确认报文（on）**：

```
{
  "meta": {
    "primitive": "on",
    "src_crid": "string",
    "dest_crid": "string",
    "path": "<复用请求的path>",
    "version": "1.0"
  },
  "header": {
    "msg_id": "string",
    "correlation_id": "string",
    "timestamp": "long",
    "ret_code": "string",
    "ret_msg": "string"
  },
  "payload": {
    "biz_code": "0",
    "biz_msg": ""
  }
}
```

**约束**：
header.ret_code/ret_msg：框架系统码，承载报文通信、解析、路由、链路层面的成功或失败。
**meta 字段定义**：

- primitive：元语原语类型，请求固定为 `"post"`；底层投递受理回执固定为 `"on"`。
- src_crid：本条报文发送端点 CRID。post 请求 src_crid 等于发起调用的 Endpoint 实例 this.crid；on 报文 src_crid 等于底层传输层端点 CRID。该字段由元语层自动填充，业务侧无需传入。
- dest_crid：本条报文投递目标端点 CRID。dest_crid + path 组合准确定位目标 Endpoint 内部的目标方法；EventBus 依靠 dest_crid 完成消息投递寻址。post 请求报文的 dest_crid 为被调用 Endpoint；on 报文 dest_crid 取自入站 post 请求 meta.src_crid（原始请求发起实体）。该字段由元语层自动填充，业务侧无需传入。
- path：接口路径表达式，与 dest_crid 配对定位方法，on 报文复用请求 path。
- version：元语协议版本。

**header 字段定义**：

- msg_id：本条消息实例唯一标识，每条消息独立生成。
- correlation_id：post 请求、on 就绪报文、后续事件报文使用完全相同的 correlation_id，用于元语层完成本次请求关联。由 post 调用的元语层在构造请求时生成。
- timestamp：报文生成时间戳。
- deadline：请求返回有效截止时间，单位统一为毫秒；值为 0 表示无超时限制。该字段由入参 ctrlMap 映射生成，元语层读取并写入 post 请求报文 header；on 报文、后续事件报文不携带 deadline。底层传输逻辑需校验 header.deadline，若当前时间已超过 deadline，直接返回链路超时错误。

payload 固定结构约定：所有 on 就绪报文 payload 必须包含 biz_code、biz_msg，字段名称固定，不可改名。

- biz_code = "0"：底层投递任务受理成功，投递通路就绪，biz_msg 可为空字符串；
- biz_code ≠ "0"：投递任务接收 / 校验失败，biz_msg 存放可读错误描述；
biz_code 枚举值由各 path 所属模块文档自行定义，元语层不约束具体取值；
当 header.ret_code ≠ "0000" 时，biz_code /biz_msg 不可信，调用方禁止依赖该组字段。

on 就绪报文不携带业务数据载荷，业务中间分片、输出结果交由后续独立事件推送。
发起调用方收到 on 就绪报文直接交付本次 post 调用点，不进入发起方 on 事件处理器。调用方元语层同样校验 deadline，超时直接抛出链路异常。
on 报文 header.correlation_id 原样复制 post 请求报文的 correlation_id；on 报文生成独立新 msg_id。
on 报文 meta.src_crid = 底层传输层端点 CRID；on 报文 meta.dest_crid = post 请求报文 meta.src_crid；on 报文 meta.path 原样复制请求报文 meta.path。

post 为点对点定向投递，不做一对多广播。

**补充备注**：post 的多次分片流式输出，属于后续事件报文，不是本次 on 就绪报文内直接返回分片。后续事件报文由发起方预先注册的 on 处理器接收。

> ctrlMap 说明：CtrlMap 为可选控制参数字典，承载链路控制类配置，deadline 是其中一项配置项；后续可在 ctrlMap 扩展其他控制参数，元语层自动映射至报文 header。
