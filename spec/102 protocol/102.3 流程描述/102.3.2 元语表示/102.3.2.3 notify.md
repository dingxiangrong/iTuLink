### 102.3.2.3 notify（业务流式回调元语｜中间分片推送）

**元语签名**：notify(reqMsg: ReqMsg, payload: Payload, ctrlMap?: CtrlMap) -> ResMsg

**描述**：notify 为点对点异步推送元语，用于推送 reqMsg 所指代请求在处理过程中的中间输出、增量分片、进度状态。由业务模块主动推送到原始请求发起模块。notify 调用本地底层技术层提交报文；底层入队成功后，**元语层在本地构造 primitive=none 的返回报文对象**。该对象不是远端回传的网络报文，仅用于统一上层返回报文结构，不等待接收方执行业务消费逻辑。notify 仅承载阶段性数据，不代表请求处理完毕；请求处理完成的标记由 return 报文承载。

**元语层组包规则**：元语层自动完成消息组包，生成 meta、header 两段；业务侧仅传入 reqMsg 与 payload，可选传入 ctrlMap，无需手动填充 meta、header 字段。meta 内 `src_crid` 取自当前业务模块 CRID，`dest_crid` 由元语层从 reqMsg 上下文自动提取填充。

**补充**：
header 新增 deadline，表示回调消息有效截止时间；deadline = 0 表示不限制超时。deadline 值由 ctrlMap 内配置项映射填充；ctrlMap 不传时，deadline 默认等于 0。

**请求报文（notify）**

```
{
  "meta": {
    "primitive": "notify",
    "src_crid": "string",
    "dest_crid": "string",
    "path": "<由具体接口定义>",
    "version": "1.0"
  },
  "header": {
    "msg_id": "string",
    "correlation_id": "string",
    "timestamp": "long",
    "deadline": "long"
  },
  "payload": {
    "<分片/进度业务参数由具体 path 定义>"
  }
}
```

**本地构造返回报文（primitive="none"）**

```
{
  "meta": {
    "primitive": "none",
    "src_crid": "string",
    "dest_crid": "string",
    "path": "<复用请求的path>",
    "version": "1.0"
  },
  "header": {
    "msg_id": "string",
    "correlation_id": "string",
    "timestamp": "long",
    "deadline": "long",
    "ret_code": "string",
    "ret_msg": "string"
  },
  "payload": {
    "biz_code": "0",
    "biz_msg": ""
  }
}
```

**约束**：
header.ret_code/ret_msg：框架系统码，承载报文通信、解析、路由、链路层面的成功或失败。
**meta 字段定义**：

- primitive：元语原语类型，notify 请求报文固定为 `"notify"`；本地构造返回报文 primitive 固定为 `"none"`。
- src_crid：本条报文发送端点 CRID，notify 报文发送方为业务处理模块，由元语层自动填充，业务侧无需传入。
- dest_crid：本条报文投递目标实体 CRID。**dest_crid + path 组合准确定位目标实体内部的目标方法**；EventBus 依靠 dest_crid 完成消息投递寻址。notify 请求报文 dest_crid 为原始请求发起实体。该字段由元语层自动填充，业务侧无需传入。
- path：接口路径表达式，与 dest_crid 配对定位方法。
- version：元语协议版本。

**header 字段定义**：

- msg_id：本条消息实例唯一标识，每条消息独立生成。
- correlation_id：notify 报文必须填充有效 correlation_id，取自 reqMsg，用于关联原始请求。
- timestamp：报文生成时间戳。
- deadline：回调消息有效截止时间，单位统一为毫秒；值为 0 表示无时间限制。该字段由入参 ctrlMap 映射生成，ctrlMap 不传默认填充 0，元语层读取并写入报文 header。接收方处理前校验 header.deadline，若当前时间已超过 deadline，直接丢弃本条 notify 报文。

入站 notify 报文抵达模块，进入该模块 on (事件报文) 统一入口，识别元语类型后执行业务消费逻辑。
notify 为点对点定向推送，仅投递至 reqMsg 对应的原始请求发起模块。
primitive="none" 为**本地内存构造的返回对象**，不是远端网络回传报文；仅用于统一上层返回报文结构，作为 EventBus 传输层内部入队确认，用于释放发送侧资源，业务代码不基于该报文做业务逻辑判断。
返回报文 header.correlation_id、deadline 原样复制 notify 请求报文对应字段；返回报文生成独立新 msg_id。
返回报文 meta.dest_crid 填充为 notify 请求报文的发送实体 CRID；返回报文 meta.path 原样复制请求报文 meta.path。

payload 承载分片、进度、中间输出等业务数据，内部结构由具体 path 接口文档定义。
notify 可连续多次推送；当收到对应 correlation_id 的 return 报文后，该 correlation_id 后续 notify 报文全部丢弃。

> ctrlMap 说明：CtrlMap 为可选控制参数字典，承载链路控制类配置，deadline 是其中一项配置项；后续可在 ctrlMap 扩展其他控制参数，元语层自动映射至报文 header。

**说明**：notify、return 均为点对点异步推送元语，共享同一套本地构造返回报文结构；语义区分：notify 负责中间分片 / 进度推送，return 负责任务终结、返回最终业务结果。
