# 102.3.2.4 return（业务收尾回调元语｜任务终结应答）

**元语签名**：return(reqMsg: ReqMsg, payload: Payload, ctrlMap?: CtrlMap) -> ResMsg

**描述**：return 为点对点异步推送元语，由业务模块主动推送到原始请求发起模块。return 调用本地底层技术层提交报文；底层入队成功后，**元语层在本地内存构造 primitive=none 的返回报文对象**。该对象不是远端回传的网络报文，仅用于统一上层返回报文结构。return 报文一旦发出，代表针对该 reqMsg 的业务处理生命周期结束，不再继续产生针对该 reqMsg 的后续推送报文。

**元语层组包规则**：元语层自动完成消息组包，生成 meta、header 两段；业务侧仅传入 reqMsg 与 payload，可选传入 ctrlMap，无需手动填充 meta、header 字段。meta 内 `src_crid` 取自当前业务模块 CRID，`dest_crid` 由元语层从 reqMsg 上下文自动提取填充。

**补充**：
header 新增 deadline，表示回调消息有效截止时间；deadline = 0 表示不限制超时。deadline 值由 ctrlMap 内配置项映射填充；ctrlMap 不传时，deadline 默认等于 0。

**输入参数说明**
reqMsg：原始请求消息实例，用于提取标识，生成本回调报文的 correlation_id
payload：本次返回的业务载荷

**请求报文（return）**

```
{
  "meta": {
    "primitive": "return",
    "src_crid": "string",
    "dest_crid": "string",
    "path": "<由具体接口定义>",
    "version": "1.0"
  },
  "header": {
    "msg_id": "string",
    "correlation_id": "string",
    "timestamp": "long",
    "deadline": "long"
  },
  "payload": {
    "biz_code": "0",
    "biz_msg": "",
    "data": { ... }
  }
}
```

**本地构造返回报文（primitive="none"）**

```
{
  "meta": {
    "primitive": "none",
    "src_crid": "string",
    "dest_crid": "string",
    "path": "<复用请求的path>",
    "version": "1.0"
  },
  "header": {
    "msg_id": "string",
    "correlation_id": "string",
    "timestamp": "long",
    "deadline": "long",
    "ret_code": "string",
    "ret_msg": "string"
  },
  "payload": {
    "biz_code": "0",
    "biz_msg": ""
  }
}
```

**约束**：
header.ret_code/ret_msg：框架系统码，承载报文通信、解析、路由、链路层面的成功或失败。
**meta 字段定义**：

- primitive：元语原语类型，return 请求报文固定为 `"return"`；本地构造返回报文 primitive 固定为 `"none"`。
- src_crid：本条报文发送端点 CRID，return 报文发送方为业务处理模块，由元语层自动填充，业务侧无需传入。
- dest_crid：本条报文投递目标实体 CRID。**dest_crid + path 组合准确定位目标实体内部的目标方法**；EventBus 依靠 dest_crid 完成消息投递寻址。return 请求报文 dest_crid 为原始请求发起实体。该字段由元语层自动填充，业务侧无需传入。
- path：接口路径表达式，与 dest_crid 配对定位方法。
- version：元语协议版本。

**header 字段定义**：

- msg_id：本条消息实例唯一标识，每条消息独立生成。
- correlation_id：return 报文必须填充有效 correlation_id，取自 reqMsg，用于关联原始请求。
- timestamp：报文生成时间戳。
- deadline：回调消息有效截止时间，单位统一为毫秒；值为 0 表示无时间限制。该字段由入参 ctrlMap 映射生成，ctrlMap 不传默认填充 0，元语层读取并写入报文 header。接收方处理前校验 header.deadline，若当前时间已超过 deadline，直接丢弃本条 return 报文。

入站 return 报文抵达模块，进入该模块 on (事件报文) 统一入口，识别元语类型后执行业务消费逻辑。
return 为点对点定向推送，仅投递至 reqMsg 对应的原始请求发起模块。
primitive="none" 为**本地内存构造的返回对象**，不是远端网络回传报文；仅用于统一上层返回报文结构，作为 EventBus 传输层内部入队确认，用于释放发送侧资源，业务代码不基于该报文做业务逻辑判断。
本地构造返回报文 header.correlation_id、deadline 原样复制 return 请求报文对应字段；返回报文生成独立新 msg_id。
返回报文 meta.dest_crid 填充为 return 请求报文的发送实体 CRID；返回报文 meta.path 原样复制请求报文 meta.path。

payload 固定结构约定：return 的 payload 必须包含 biz_code、biz_msg，字段名称固定，不可改名。

- biz_code = "0"：业务执行成功，biz_msg 可为空字符串或省略；
- biz_code ≠ "0"：业务执行失败，biz_msg 存放可读业务错误描述；调用方识别到非 0 biz_code，直接忽略 payload.data 内容。
biz_code 枚举值由各 path 所属模块文档自行定义，元语层不约束具体取值；
payload.data：承载最终业务主体载荷，内部结构由具体 path 接口文档定义。业务失败场景下 data 建议置 null，由各 path 接口按需说明。

收到对应 correlation_id 的 return 报文后，该 correlation_id 后续 notify 报文全部丢弃。

> ctrlMap 说明：CtrlMap 为可选控制参数字典，承载链路控制类配置，deadline 是其中一项配置项；后续可在 ctrlMap 扩展其他控制参数，元语层自动映射至报文 header。

**说明**：notify、return 均为点对点异步推送元语，共享同一套本地构造返回报文结构；语义区分：notify 负责中间分片 / 进度推送，return 负责任务终结、返回最终业务结果。
