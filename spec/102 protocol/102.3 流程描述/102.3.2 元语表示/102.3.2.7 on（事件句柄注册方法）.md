### 102.3.2.7 on（事件句柄注册方法）

**元语类别**：事件句柄注册元语
**元语语法**：
`on(pattern: PatternExpr, handler: () -> Msg)`

**语义**：向组件运行时注册事件句柄，作为本组件唯一的报文接收入口。将路由匹配模式 pattern 绑定至无参事件句柄 handler；运行时，所有流入本组件的报文（无论 call 请求、post 请求、emit 事件、forward 转发）统一进入 on，依靠报文内部 meta.primitive + meta.path 完成路由解析与业务分发，实现接收层归一化。on 不区分元语来源，对全部入站报文执行模式匹配；匹配成功则将报文挂载至当前协程 / 线程上下文，执行该 handler。

**参数定义**：
`pattern: PatternExpr`：路由匹配模式，纯文本字符串。
匹配规则钉定：
精确匹配："alert"，仅路由标识完全等于 alert 时命中。
单层前缀通配："chat/*"。*仅匹配单个路径段，不包含 /。
命中：chat/msg、chat/alert
不命中：chat/alert/ack（含二级 /）
全局兜底模式："*"，捕获所有未被前面 pattern 命中的路由。

注册约束：全局兜底`on("*", handler)`必须在全部其余 pattern 注册完成之后，作为最后一条注册。框架注册阶段做校验，若兜底`*`非最后注册，抛出配置异常。

`handler: () -> Msg`：事件句柄函数。

- 签名：() -> Msg，无形式入参。
- 运行时读取：事件报文、ReqMsg 从运行时上下文获取，不通过函数参数传入。
- 返回值：Msg，事件句柄业务逻辑执行完成后向上输出消息对象。

**注册示例**：

```
on("chat/*", ->handleChat)     // 匹配 chat/一级子路径，不穿透多级
on("alert", ->handleAlert)     // 精确匹配 alert
on("*", ->handleFallback)      // 全局兜底，必须最后注册
```

**描述**：on（事件句柄注册方法）。所有流入组件的报文，无论 call 请求、post 请求、emit 事件、forward 转发，全部经由 on 统一接收。on 不区分元语来源，入站后靠报文内部 meta.primitive + meta.path 完成路由解析与业务分发，实现接收层归一化。call 应答报文由框架直接交付调用点，不进入 on，属于技术层分发，不在本监听语义范畴内。

**刚性规则**
发送侧路由选择：

- 任务下发、指令流转、长任务执行、数据回流、分片输出 → 一律走 post
- 生命周期事件、状态变更、就绪通知、顶层广播 → 一律走 emit
- 1 次请求 → 1 次响应 → 调用方拿到结果继续走 → 一律走 call

接收侧归一化：所有入站请求与事件，统一走 on 单入口接收，禁止按元语类型分化多个监听入口。

**约束**：
on 属于接收侧元语，仅用于监听捕获流入本组件的各类报文；不负责向外发送报文。向外发送报文只能选用 call /post/emit /forward。
入站 call 请求报文同样会先进入服务端 on 统一入口，识别元语类型后路由至对应业务处理函数；call 应答报文直接交付发起方 call 调用点，不进入发起方的 on。
on 仅做报文接收、元语识别与路由分发，不直接定义对外可寻址的接口方法。
on 是注册事件句柄函数，并非主动发送报文的调用元语。
