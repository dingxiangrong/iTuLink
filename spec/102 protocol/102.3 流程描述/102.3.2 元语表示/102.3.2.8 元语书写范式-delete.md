# 102.3.2.8 元语书写范式

**边界说明**：本章节仅定义外层元语语法与交互流转时序。所有调用、事件的参数内部字段、数据结构，不在本章做规约。组件内部运算、内部初始化、状态切换、实例销毁逻辑，属于组件自身职责，不属于跨组件交互，不在本章流程罗列。外部实体不通过 post 指令驱动对方内部状态变更。

**Msg 抽象对象**：ReqMsg（请求消息）、ResMsg（应答消息），均属于 Msg 子类。业务侧传入 payload，框架封装为 ReqMsg 向外投递；远端应答产出 ResMsg。本章仅定义元语与 Msg 的契约，Msg 内部字段后置至模块文档定义。

## 元语定义：on 元语｜处理器注册元语

**元语语法**：

```
on(pattern: PatternExpr, handler: () -> Msg)
```

**语义**：向组件运行时注册事件处理器。将路由匹配模式 pattern 绑定至无参处理器函数 handler；运行时，入站事件报文的路由标识按模式匹配规则比对 pattern，匹配成功则将报文挂载至当前协程 / 线程上下文，执行该 handler。

**pattern: PatternExpr**：路由匹配模式，纯文本字符串
匹配规则钉定：

- 精确匹配：`"alert"`，仅路由标识完全等于 alert 时命中
- 单层前缀通配：`"chat/*"`。`*`仅匹配单个路径段，不包含`/`。
  - 命中：`chat/msg`、`chat/alert`
  - 不命中：`chat/alert/ack`（含二级`/`）
- 全局兜底模式：`"*"`，捕获所有未被前面 pattern 命中的路由

注册约束：全局兜底`on("*", handler)`必须在全部其余 pattern 注册完成之后，作为最后一条注册。框架注册阶段做校验，若兜底`*`非最后注册，抛出配置异常。

**handler: () -> Msg**：事件处理器函数

- 签名：`() -> Msg`，无形式入参
- 运行时读取：事件报文、ReqMsg 从运行时上下文获取，不通过函数参数传入
- 返回值：Msg，处理器业务逻辑执行完成后向上输出消息对象

注册示例（纯文本 pattern）

```
on("chat/*", ->handleChat)     // 匹配 chat/一级子路径，不穿透多级
on("alert", ->handleAlert)     // 精确匹配 alert
on("*", ->handleFallback)      // 全局兜底，必须最后注册
```

## 1. call —— 同步请求元语

**函数签名**：`call(path: PathExpr, payload: Payload, ctrlMap?: CtrlMap) -> ResMsg`

**输入参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| path | PathExpr | 是 | 业务路由标识，用于目标组件 on 的 pattern 匹配 |
| payload | Payload | 条件 | 业务原始载荷；框架自动将 payload 封装生成 ReqMsg 向外发送 |
| ctrlMap | CtrlMap | 否 | 链路控制参数字典，用于填充 header.deadline；不传则 deadline=0（无超时限制） |

**返回参数**：

| 返回 | 类型 | 说明 |
| --- | --- | --- |
| ResMsg | Msg | 远端应答产出的应答消息对象；call 调用阻塞直至 ResMsg 送达 |

**使用方法**：
调用方传入 path、业务 payload，可选传入 ctrlMap；call 元语框架自动构造 ReqMsg；
ReqMsg 打包为事件报文投递至目标组件；
底层取出报文路由 path，遍历已注册 pattern 列表，按注册顺序做模式匹配；
匹配成功，挂载事件报文至运行时上下文，触发对应已注册 handler: () -> Msg；
handler 执行，向上返回 Msg；框架读取上下文 reqMsg，提取 Msg 内 payload，调用 `return (reqMsg, payload)` 回传；
ResMsg 回传给 call 调用点，阻塞解除，调用方拿到 ResMsg。

**约束**：单条 call 请求会话，仅允许执行一次 return；多次 return 视为契约违规。

## 2. post —— 异步投递元语

**函数签名**：`post(path: PathExpr, payload: Payload, ctrlMap?: CtrlMap) -> SysMsg`
后续回调接收：`notify(reqMsg, payload)` + `return(reqMsg, payload)`

**输入参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| path | PathExpr | 是 | 业务路由标识，用于目标组件 on 的 pattern 匹配 |
| payload | Payload | 条件 | 业务原始载荷；框架自动封装生成 ReqMsg 投递 |
| ctrlMap | CtrlMap | 否 | 链路控制参数字典，用于填充 header.deadline；不传则 deadline=0（无超时限制） |

**返回参数**：
SysMsg：技术状态回执。仅表达本次投递动作技术上成功 / 失败，不代表业务执行结果。

**使用方法**：
调用方预先注册 on 处理器，用于接收本次会话后续的 notify、return 应答报文；
调用方执行 `post(path, payload, ctrlMap)`，框架生成 ReqMsg；
框架执行参数校验、pattern 路由匹配、报文序列化；
框架返回 SysMsg：

- 技术成功：报文入队，不阻塞当前执行；等待远端 handler 执行并输出应答报文；
- 技术失败：直接返回失败 SysMsg，不会发起远端调用、不会产生 notify/return 报文；

远端侧：底层收到事件报文，取出路由 path，按注册顺序遍历 pattern 做模式匹配；
匹配成功，挂载报文上下文，触发目标组件注册 handler: () -> Msg；
handler 执行，返回 Msg。分片逻辑不由框架自动处理；业务代码主动多次调用 `notify (reqMsg, payload)` 推送中间过程数据，最终调用 `return (reqMsg, payload)` 终结会话。

远端输出的 notify、return 应答报文，路由回发起方组件；发起方底层收到报文，执行 pattern 匹配，触发预先注册的 on 处理器接收 ResMsg。会话收到 return 报文后标记会话闭合，丢弃同 correlation_id 后续消息。

## 3. emit —— 广播事件元语

**函数签名**：`emit(event-path: PathExpr, payload: Payload, ctrlMap?: CtrlMap) -> void`

**输入参数**:

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| event-path | PathExpr | 是 | 事件路由标识，对所有订阅组件的 on pattern 执行匹配 |
| payload | Payload | 条件 | 事件原始载荷；框架自动封装生成 ReqMsg 单向广播推送 |
| ctrlMap | CtrlMap | 否 | 链路控制参数字典，用于填充 header.deadline；不传则 deadline=0（无超时限制） |

**返回参数**：无返回值。

**使用方法**：
发送方传入 event-path 与 payload，可选传入 ctrlMap；emit 框架生成 ReqMsg 广播；
每个订阅组件独立执行：取出报文 path，遍历本组件注册 pattern 顺序匹配；匹配成功则挂载上下文，触发组件 handler: () -> Msg；
handler 执行，返回 Msg；emit 场景下，该 Msg 仅本地消费，不对外投递应答报文；
消费异常由接收方自行处理，发送方无感知。

## 4. return —— 会话终结应答元语

**函数签名**：`return(reqMsg: ReqMsg, payload: Payload, ctrlMap?: CtrlMap) -> ResMsg`

**输入参数**:

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| reqMsg | ReqMsg | 是 | 原始请求消息对象，提取会话标识（msg_id/correlation_id），绑定本次应答 |
| payload | Payload | 是 | 应答业务载荷；框架基于 reqMsg 上下文 + payload 封装生成 ResMsg 回传 |
| ctrlMap | CtrlMap | 否 | 链路控制参数字典，用于填充 header.deadline；不传则 deadline=0（无超时限制） |

**返回参数**:

| 返回 | 类型 | 说明 |
| --- | --- | --- |
| ResMsg | Msg | 应答消息，路由送达原始发起方 |

**使用方法**:
业务处理完成，传入原始 reqMsg、应答 payload，可选传入 ctrlMap；return 元语框架读取 reqMsg 的关联上下文，生成 ResMsg；
ResMsg 自动绑定 correlation_id，路由回原始请求发起方；

**约束**：同一请求会话，return 仅允许调用一次；return 执行后，禁止再发送 notify。

## 5. notify —— 过程流式应答元语

**函数签名**：`notify(reqMsg: ReqMsg, payload: Payload, ctrlMap?: CtrlMap) -> ResMsg`

**输入参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| reqMsg | ReqMsg | 是 | 原始请求消息对象，提取会话标识，绑定本次过程应答 |
| payload | Payload | 是 | 过程分片 / 进度载荷；框架基于 reqMsg 上下文 + payload 封装生成 ResMsg 推送 |
| ctrlMap | CtrlMap | 否 | 链路控制参数字典，用于填充 header.deadline；不传则 deadline=0（无超时限制） |

**返回参数**：

| 返回 | 类型 | 说明 |
| --- | --- | --- |
| ResMsg | Msg | 过程应答消息，路由送达发起方 |

**使用方法**：
post 会话内，业务主动多次调用 notify，传入原始 reqMsg 与 payload，可选传入 ctrlMap；
notify 元语框架读取 reqMsg 上下文，自动封装为 ResMsg，底层投递至发起方；
发起方底层收到报文，提取 path 执行 pattern 匹配、缓存上下文，触发注册 handler，接收 ResMsg 序列，做聚合处理，直到收到 return 终结 ResMsg。

**约束**：仅能在同一会话 return 之前调用；return 调用后禁止 notify。

## 6. forward —— 组件内部转发元语

**函数签名**：forward(msg: Msg, iface: InterfaceId) -> SysMsg

**输入参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|msg|Msg|是|待完整透传的原始消息对象，保留原始事件全部元语标识、path、msg_id、correlation_id|
|iface|InterfaceId|是|SV 选定的路由出口标识，用于选择报文从哪个对外 interface 送出，不写入转发出去的报文|

**返回参数**：

SysMsg：技术状态回执。仅表达本次投递动作技术上成功 / 失败，不代表业务执行结果。

> **说明**：forward 仅限 SV 路由实体调用，其余模块禁止使用；msg.meta.path 为原始业务 path，dest 仅用于 SV 寻址，不修改原始 Msg 本体。

---

# 二、报文打包规则

调用 call /post/emit /forward 时，元语框架自动执行打包：
meta 段：primitive（元语类型）、path、version；
header 段：msg_id、correlation_id、timestamp、deadline；deadline 取自 ctrlMap，不传默认 0；
payload 段：将业务载荷封装进 ReqMsg，放入报文 payload；无业务载荷时 ReqMsg 留空；
生成标准化事件报文，交由底层传输投递。

return /notify 调用时，入参携带 reqMsg，元语框架自动打包：
meta 段：primitive（return/notify）；
header 段：从 reqMsg 提取 correlation_id、timestamp、deadline；
payload 段：业务载荷封装进 ResMsg；
应答报文交由底层路由回原始发起方。

# 三、on 完整调度时序（修订分派逻辑）

注册期：组件初始化阶段，顺序执行元语 `on(pattern: PatternExpr, handler: () -> Msg)`，按注册先后存入组件路由匹配表。先注册优先匹配，兜底`*`强制最后注册。

运行期 Step1：底层传输层接收网络消息，组装事件报文。
运行期 Step2：提取报文内路由 path。
运行期 Step3：遍历路由匹配表，逻辑语义等价于按注册顺序依次使用 pattern 与 path 做模式比对，命中首个匹配项即短路终止遍历。

> 实现备注：为应对 pattern 数量较多场景，框架底层实现可构建前缀索引、Trie 树等结构优化匹配性能；但对外暴露的匹配语义必须等价于顺序短路匹配，不可改变匹配优先级。
> 运行期 Step4：将事件报文挂载至当前运行上下文。
> 运行期 Step5：调用 handler ()；handler 内部读取上下文获取事件报文与 ReqMsg。
> 运行期 Step6：handler 返回 Msg；运行时依据会话类型，选择调用 return，post 场景交由业务自主控制 notify/return，emit 场景丢弃应答投递。

# 四、分支语义

- call：handler 返回 Msg → 提取 payload，调用 `return (reqMsg, payload)`，单向回送终结 ResMsg，阻塞等待。
- post：handler 返回 Msg → 业务主动调用多次 `notify (reqMsg, payload)` 推送中间数据，最终调用 `return (reqMsg, payload)` 关闭会话；框架不自动拆分 Msg。
- emit：handler 返回 Msg → 仅本地使用，不向外发送应答报文。
- forward：转发报文至目标角色地址 dest，目标组件执行 pattern 匹配、handler 独立执行；应答链路穿透至原始发起方。

# 核心规约汇总

1. on：处理器注册元语，语法`on(pattern: PatternExpr, handler: () -> Msg)`
2. handler 处理器函数：`() -> Msg`，无形式参数，报文从运行上下文读取
3. pattern 规则：`*`单层匹配，不跨`/`；全局兜底`on("*",...)`强制最后注册，框架注册期校验报错
4. 分派语义：顺序短路匹配；底层实现可索引优化，语义不变
5. post 流式应答：业务主动调用 notify，框架不自动分片 Msg
6. ReqMsg、ResMsg 均为 Msg 子类，由元语框架自动构造
7. return、notify 入参固定为`(reqMsg: ReqMsg, payload: Payload, ctrlMap?: CtrlMap)`
8. 发送类元语 call/post/emit/notify/return 增加可选 ctrlMap，用于映射 header.deadline；forward 不增加 ctrlMap（透传原始报文控制信息）
