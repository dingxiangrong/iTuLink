### 102.4.1.1 emit session-event(session-in)

**元语签名**：`emit(event-path: "session-event", payload: SessionInEvent, ctrlMap?: CtrlMap) -> void`
**描述**：外部宿主 UPP emit 输出 session-event (session-in)，事件输入 iTuLink 链路，被 SV 监听接收。
**生产者**：UPP
**契约消费者**：SV

emit 为体系广播单向事件元语，事件发送方不阻塞、不等待应答；消费者订阅对应 event-path 接收事件。

**请求 payload**

```
{
  "sessionId": "string",
  "eventId": "string",
  "event_type": "session_in",
  "user_info": {
    "user_id": "string",
    "user_label": "string",
    "avatar": "string",
    "position": "string"
  }
}
```

**Payload 字段说明**

- `sessionId`：会话全局唯一标识，为本事件创建的顶层会话主键，后续会话相关事件均以此 ID 作为检索依据。
- `eventId`：本会话初始化事件的全局唯一标识，用于事件追踪、日志审计、事件去重。
- `event_type`：事件类型标识，固定取值为`session_in`，用于事件路由识别。
- `user_info`：当前会话绑定的用户基础信息对象。
  - `user_id`：用户全局唯一标识，全链路引用，**必填**。
  - `user_label`：用户可读名称，**必填**。
  - `avatar`：用户头像资源地址，可选扩展字段。
  - `position`：用户职务，可选扩展字段。

> **扩展约定**：`user_info`支持后续按需新增其他扩展字段；消费方解析时必须忽略无法识别的扩展字段，保障协议向前兼容。

**响应**：无。emit 单向事件，不存在响应报文。

**约束**
SV 监听到本 session_in 事件后，逐条串行调用四类查询接口，向外部宿主 UPP 及 CC 拉取元数据，构建本地会话能力空间并缓存会话元数据。调用顺序（二级 post 事件，逐条执行，前一条完成再发起下一条）：

1. post upp-meta-get：访问 UPP，查询会话身份、权限、有效期，完成会话合法性备案。
2. post upp-cc-enum：访问 UPP，枚举当前会话绑定的 CC 容器实例 ID 与挂载状态，得到可调度容器清单。
3. post cc-meta-get：基于容器清单，查询每个 CC 容器基础属性、运行状态、版本信息。
4. post cc-cap-enum：向 CC 枚举容器内全部可用能力清单、能力启停状态，构建本地能力索引。
