### 102.4.1.2 emit session-event (session-out)

**元语签名**：`emit(event-path: "session-event", payload: SessionOutEvent, ctrlMap?: CtrlMap) -> void`
**描述**：外部宿主 UPP emit 输出 session-event (session-out)，事件输入 iTuLink 链路，被 SV 监听接收。
**生产者**：UPP
**契约消费者**：SV

emit 为体系广播单向事件元语，事件发送方不阻塞、不等待应答；消费者订阅对应 event-path 接收事件。

**请求 payload**

```
{
  "sessionId": "string",
  "eventId": "string",
  "event_type": "session_out"
}
```

**Payload 字段说明**

- `sessionId`：会话全局唯一标识，为本事件作用的目标会话主体。会话销毁操作以该 sessionId 作为检索主键。
- `eventId`：本会话退出事件的全局唯一标识，用于事件追踪、日志审计与事件去重。
- `event_type`：事件类型标识，固定取值为`session_out`，用于事件路由识别。

**响应**：无。emit 单向事件，不存在响应报文。

**约束**
SV 监听到本 session_out 事件后，清空当前 sessionId 对应的本地会话能力空间缓存，标记该会话下全部关联事件、能力调度链路永久失效，终止本轮会话所有业务流转。
会话销毁作用域：当前 sessionId 下全部 conversation、chatId 任务链路一并终止，不再接受该会话下任何新事件。
event_type 固定取值 session_out。
eventId 为本会话退出事件全局唯一标识。
仅当 sessionId 存在且会话处于有效状态时事件生效；会话不存在或已销毁直接丢弃事件。
会话销毁后，相关缓存清理策略由 SV 内部管控，规范不约束底层持久化清理细节。

### 102.4.1.4 emit focus-event (focus-out)

**元语签名**：`emit(event-path: "focus-event", payload: FocusOutEvent, ctrlMap?: CtrlMap) -> void`
**描述**：CC 广播 Cap 能力失活退出事件。emit 为单向广播事件，无应答。
**生产者**：CC
**契约消费者**：SV

**请求 payload**

```
{
  "sessionId": "string",
  "eventId": "string",
  "event_type": "focus_out",
  "action_id": "string",
  "cc_id": "string",
  "cap_id": "string"
}
```

**Payload 字段说明**

- `sessionId`：会话全局唯一标识
- `eventId`：本失活退出事件的全局唯一标识
- `event_type`：事件类型，固定为`focus_out`
- `action_id`：本次失活动作唯一标识，与配对 focus-in 事件 action_id 保持一致
- `cc_id`：能力容器 CC 的唯一标识，仅用于定位 CC 容器，**不能单独全局定位 Cap**
- `cap_id`：Cap 在所属 CC 容器内的局部 ID，仅在当前 CC 内部唯一，**不能单独全局定位 Cap**

> 
> 重点：`cc_id + cap_id` 联合构成全局唯一 Cap 定位。必须成对使用，二者任一单独取值都无法完成全局 Cap 寻址。

**响应**：无。emit 单向事件，不存在响应报文。

**约束**

1. SV 监听到本 focus_out 事件后，清空本地缓存内对应 action_id、`cc_id + cap_id` 的聚焦能力上下文、能力配置与调度规则，标记该 Cap 为空闲未激活状态。
2. action_id：本次失活退出的动作唯一标识，与 focus_in 事件的 action_id 一一对应。
3. 仅销毁该 action 绑定 Cap 的能力上下文，**不改动顶层 session、conversation 生命周期**。
4. 若本地不存在该 action + cc_id + cap_id 的缓存记录，直接丢弃事件，不抛出异常。
