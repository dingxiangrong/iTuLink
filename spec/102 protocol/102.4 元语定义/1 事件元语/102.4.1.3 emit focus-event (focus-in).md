### 102.4.1.3 emit focus-event (focus-in)

**元语签名**：`emit(event-path: "focus-event", payload: FocusInEvent, ctrlMap?: CtrlMap) -> void`
**描述**：CC 广播 Cap 能力聚焦激活事件。emit 为单向广播事件，无应答。
**生产者**：CC
**契约消费者**：SV

**请求 payload**

```
{
  "sessionId": "string",
  "eventId": "string",
  "event_type": "focus_in",
  "cc_id": "string",
  "cap_id": "string"
}
```

**Payload 字段说明**

- `sessionId`：会话全局唯一标识
- `eventId`：本聚焦激活事件的全局唯一标识
- `event_type`：事件类型，固定为`focus_in`
- `cc_id`：能力容器 CC 的唯一标识，仅用于定位 CC 容器，**不能单独全局定位 Cap**
- `cap_id`：Cap 在所属 CC 容器内的局部 ID，仅在当前 CC 内部唯一，**不能单独全局定位 Cap**

> **重点**：`cc_id + cap_id` 联合构成全局唯一 Cap 定位。必须成对使用，二者任一单独取值都无法完成全局 Cap 寻址。

**响应**：无。emit 单向事件，不存在响应报文。

**约束**

1. SV 监听到本 focus_in 事件后，在本地缓存建立 `cc_id + cap_id` 联合主键的聚焦能力上下文，记录能力配置与调度规则，标记该 Cap 为激活聚焦状态。
2. 仅创建 / 激活该 Cap 能力上下文，**不改动顶层 session、conversation 生命周期**。
3. 若同 `cc_id + cap_id` 已存在激活上下文，直接覆盖更新，不抛出异常。
