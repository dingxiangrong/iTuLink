### 102.4.2.1 call upp-meta-get

**元语签名**：call(destEp: Endpoint, path: "upp-meta-get", payload: UppMetaGetParams, ctrlMap?: CtrlMap) -> ResMsg

- destEp：目标端点，此处为**UPP 实例对应的 Endpoint 对象**。 

**描述**：call upp-meta-get（接口方法元语｜同步定向查询）。SV 调用 UPP 暴露的接口，获取 UPP 元数据，读取 UPP 主体描述等静态元信息。

 **请求 payload**

```
{ }
```

**响应 payload**

```
{
  "biz_code": "0",
  "biz_msg": "",
  "data": {
    "crid": "string",
    "name": "string",
    "desc": "string",
    "icon": "string",
    "semanticDesc": "string",
    "version": "string"
  }
}
```

**Payload 字段说明（响应）**

- biz_code：业务状态码，"0" 代表调用成功；非 0 代表业务异常。
- biz_msg：业务提示信息，成功时为空字符串，异常时存放错误描述文本。
- data：UPP 主体元数据对象，继承 SemanticSubject 全部基础字段。
- crid：UPP 实体 CRID，实体唯一标识。CRID 绑定独立事件队列；事件总线依靠该 CRID 定位 UPP 对应的事件队列，完成事件投递。
- name：UPP 可读名称。
- desc：UPP 简短描述文本。
- icon：UPP 图标资源地址。
- semanticDesc：UPP 语义描述文本。
- version：UPP 版本号，遵循 SemVer 规范；无版本信息填空字符串。
**约束**

1. 响应 payload.data 内 UPP 对象继承 SemanticSubject 全部基础字段。
2. version 字段遵循 SemVer 规范，无版本时填空字符串。
3. 若查询目标 UPP CRID 不存在，biz_code 返回错误码，payload.data 置为 null。
4. CRID 为实体唯一标识，每一个 CRID 对应一条独立事件队列。进程内事件总线依据 CRID 定位目标事件队列，完成事件投递。UPP、CC、SE 为该体系下的实体，每个实体实例分配独立 CRID 与专属事件队列；SV 为壳式组件，不占用独立 CRID，注册所用 CRID 即 CDT 的 CRID。事件投递入队列之后，实体内部消费处理逻辑，由实体自行实现，协议不做规定。
5. 框架层校验规则沿用 call 元语通用约定：当 header.ret_code ≠ "0000" 时，biz_code /biz_msg 不可信，调用方禁止依赖。
