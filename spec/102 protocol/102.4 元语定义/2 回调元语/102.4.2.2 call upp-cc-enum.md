### 102.4.2.2 call upp-cc-enum（修订定稿，对齐上层 call 签名）

**元语签名**：call(destEp: Endpoint, path: "upp-cc-enum", payload: UppCcEnumParams, ctrlMap?: CtrlMap) -> ResMsg

- destEp：目标端点，此处为**UPP 实例对应的 Endpoint 对象**。 


**描述**：call upp-cc-enum（接口方法元语｜同步定向查询）。SV 调用 UPP 暴露的接口，拉取 UPP 包含的能力容器列表，枚举 UPP 下属 CC 容器清单。

**请求 payload**

```
{ }
```

**响应 payload**

```
{
  "biz_code": "0",
  "biz_msg": "",
  "data": {
    "cc_list": [
      {
        "crid": "string",
        "name": "string",
        "desc": "string",
        "icon": "string",
        "semanticDesc": "string",
        "version": "string",
        "cc_type": "sovereign|autonomous"
      }
    ]
  }
}
```

**Payload 字段说明（响应）**

- biz_code：业务状态码，"0" 代表调用成功；非 0 代表业务异常。
- biz_msg：业务提示信息，成功时为空字符串，异常时存放错误描述文本。
- data：返回数据载体。
- cc_list：UPP 下属 CC 能力容器实例数组。数组内 CC 对象继承 SemanticSubject 基础字段。
- crid：CC 实体 CRID，实体唯一标识。CRID 绑定独立事件队列；事件总线依靠该 CRID 定位目标 CC 实体对应的事件队列，完成事件投递。
- name：CC 可读名称。
- desc：CC 简短描述文本。
- icon：CC 图标资源地址。
- semanticDesc：CC 语义描述文本。
- version：CC 版本号，遵循 SemVer 规范，无版本填空字符串。
- cc_type：容器类型，取值 sovereign（主权类）、autonomous（自治类）。
**约束**

1. 数组内 CC 对象继承 SemanticSubject 基础字段；cc_type 区分主权类 sovereign、自治类 autonomous 能力容器。
2. CRID 为实体唯一标识，每一个 CRID 对应一条独立事件队列。进程内事件总线依据 CRID 定位目标事件队列，完成事件投递。UPP、CC、SE 为该体系下的实体，每个实体实例分配独立 CRID 与专属事件队列；SV 为壳式组件，不占用独立 CRID，注册所用 CRID 即 CDT 的 CRID。事件投递入队列之后，实体内部消费处理逻辑，由实体自行实现，协议不做规定。
3. UPP 与 CC 仅为逻辑权责划分，物理可同部署 / 同进程。
4. upp CRID 合法但未关联任何能力容器时，biz_code 返回 "0"，data.cc_list 返回空数组 []，不视为业务错误。
5. 框架层校验规则沿用 call 元语通用约定：当 header.ret_code ≠ "0000" 时，biz_code /biz_msg 不可信，调用方禁止依赖。
