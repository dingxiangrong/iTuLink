# 102.4.2.4 call cc-cap-enum

**元语签名**：call(destEp: Endpoint, path: "cc-cap-enum", payload: CcCapEnumParams, ctrlMap?: CtrlMap) -> ResMsg

- destEp：目标端点，此处为**CC 实例对应的 Endpoint 对象**。

**描述**：call cc-cap-enum（接口方法元语｜同步定向查询）。SV 调用 CC 暴露的接口，拉取 CC 的能力列表，枚举 CC 内全部能力清单及启停状态，构建本地能力索引，支撑 CDT 推演定位至目标 Cap。CDT 推演链路：定位 CC 实体后，在 CC 作用域内推演收敛到指定 Cap。

**请求 payload**

```
{
  "cc_crid": "string"
}
```

**Payload 字段说明（请求）**

- cc_crid：CC 实体 CRID，实体唯一标识。CRID 绑定独立事件队列；事件总线依靠该 CRID 定位目标 CC 实体对应的事件队列，完成本次调用消息投递。

**响应 payload**

```
{
  "biz_code": "0",
  "biz_msg": "",
  "data": {
    "cap_list": [
      {
        "id": "string",
        "name": "string",
        "desc": "string",
        "icon": "string",
        "semanticDesc": "string",
        "version": "string",
        "capabilityType": "UI|Headless",
        "stateMode": "Stateful|Stateless",
        "input": [],
        "output": {},
        "completionCheck": {},
        "synonyms": ["string"]
      }
    ]
  }
}
```

**Payload 字段说明（响应）**

- biz_code：业务状态码，"0" 代表调用成功；非 0 代表业务异常。
- biz_msg：业务提示信息，成功时为空字符串，异常时存放错误描述文本。
- data：返回数据载体。
- cap_list：CC 下属能力实例数组。数组内 Capability 对象继承 SemanticSubject 全部基础字段。CDT 在 CC 范围内，基于本列表推演锁定目标 Cap。
- id：Cap 局部标识（cap_id）。cc_crid + cap_id 联合构成全局唯一能力定位标识；cap_id 仅在所属 CC 内部唯一。
- name：能力可读名称，给人看的名称，用于 UI 展示。
- desc：能力描述文本，给人阅读，无强制字数限制。
- icon：能力图标资源地址。
- semanticDesc：给 AI（CDT），完整语义说明，供认知推演单元做意图匹配、能力推理使用。
- version：能力版本号，遵循 SemVer 规范；无版本信息填空字符串。
- capabilityType：能力类型枚举，UI = 有界面能力，Headless = 无界面能力。
- stateMode：状态模式枚举，Stateful = 有状态，Stateless = 无状态。
- input：平行输入参数集合，类型`InputParamSpec[]`，空数组代表无输入，详见 §103.5.2 输入参数规格。
- output：顶层输出封装结构，类型`OutputSpec｜null`，null 代表无输出。
- completionCheck：无状态能力完成检测契约，类型`CompletionCheckSpec｜null`，有状态能力置 null。
- synonyms：语义目标标签数组，用于意图匹配与失败后的备选能力检索。

**约束**

1. 数组内 Capability 对象继承 SemanticSubject 全部基础字段。
2. capabilityType 枚举：UI = 有界面能力，Headless = 无界面能力；UI 类型强制 stateMode 为 Stateful。
3. stateMode 枚举：Stateful = 有状态，Stateless = 无状态。
4. input：平行输入参数集合，类型`InputParamSpec[]`，空数组代表无输入，详见 §103.5.2；output 为顶层输出封装结构，null 代表无输出。
5. completionCheck：无状态能力完成检测契约，类型`CompletionCheckSpec｜null`，有状态能力置 null。
6. synonyms：语义目标标签数组，用于意图匹配与失败后的备选能力检索。
7. 本接口返回能力级规格，不包含下属动作项私有规格；动作项规格由下游单独获取。CDT 聚焦 Cap 之后，继续向下推演定位 Cap 内 Action。
8. CRID 为实体唯一标识，每一个 CRID 对应一条独立事件队列。进程内事件总线依据 CRID 定位目标事件队列，完成事件投递。UPP、CC、SE 为该体系下的实体，每个实体实例分配独立 CRID 与专属事件队列；SV 为壳式组件，不占用独立 CRID，注册所用 CRID 即 CDT 的 CRID。事件投递入队列之后，实体内部消费处理逻辑，由实体自行实现，协议不做规定。
9. 查询的 cc_crid 不存在时，biz_code 返回错误码，payload.data 置为 null。
10. 框架层校验规则沿用 call 元语通用约定：当 header.ret_code ≠ "0000" 时，biz_code /biz_msg 不可信，调用方禁止依赖。
