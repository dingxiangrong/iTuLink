# 102.4.2.5 call cc-action-enum

**元语签名**：call(destEp: Endpoint, path: "cc-action-enum", payload: CcActionEnumParams, ctrlMap?: CtrlMap) -> ResMsg

- destEp：目标端点，此处为**CC 实例对应的 Endpoint 对象**。

**描述**：call cc-action-enum（接口方法元语｜同步定向查询）。SV 调用 CC 暴露的接口，拉取指定 Cap 下属动作项清单与动作参数规格，获取能力内部动作定义，用于参数校验、UI 表单渲染，支撑 CDT 推演寻址。CDT 推演规则：CDT 可先推演定位到目标 CC，进一步收敛至 CC 下的指定 Cap；在 Cap 作用域内，CDT 继续推演，最终聚焦到 Cap 下属的 Action。定位完成后，方可执行该 Action。


**请求 payload**

```
{
  "cc_crid": "string",
  "cap_id": "string"
}
```

**Payload 字段说明（请求）**

- cc_crid：CC 实体 CRID，实体唯一标识。CRID 绑定独立事件队列；事件总线依靠该 CRID 定位目标 CC 实体对应的事件队列，完成本次调用消息投递。
- cap_id：Cap 在 CC 内部的局部标识；cc_crid + cap_id 联合全局定位目标能力，CDT 以此推演收敛到指定 Cap。

**响应 payload**

```
{
  "biz_code": "0",
  "biz_msg": "",
  "data": {
    "action_list": [
      {
        "action_id": "string",
        "name": "string",
        "desc": "string",
        "input_params": [],
        "output_schema": {}
      }
    ]
  }
}
```

**Payload 字段说明（响应）**

- biz_code：业务状态码，"0" 代表调用成功；非 0 代表业务异常。
- biz_msg：业务提示信息，成功时为空字符串，异常时存放错误描述文本。
- data：返回数据载体。
- action_list：指定 Cap 下属动作项数组，CDT 可在 Cap 范围内推演，定位到其中单个 Action。
- action_id：动作项唯一标识，仅在所属 Cap 内唯一。cc_crid + cap_id + action_id 构成 Action 完整定位三元组。
- name：动作可读名称，给人看的名称，用于 UI 展示。
- desc：动作描述文本，给人阅读，无强制字数限制。
- input_params：动作输入参数定义数组，类型`InputParamSpec[]`，空数组代表该动作无入参，详见 §103.5.2 输入参数规格。
- output_schema：动作输出结构定义，JSON Schema；null 代表无输出。

**约束**

1. 动作项隶属于 Cap，仅在当前 Cap 作用域内有效；cc_crid + cap_id + action_id 唯一定位一个动作。CDT 依托该三元组完成逐层推演与目标锁定。
2. CRID 为实体唯一标识，每一个 CRID 对应一条独立事件队列。进程内事件总线依据 CRID 定位目标事件队列，完成事件投递。UPP、CC、SE 为该体系下的实体，每个实体实例分配独立 CRID 与专属事件队列；SV 为壳式组件，不占用独立 CRID，注册所用 CRID 即 CDT 的 CRID。事件投递入队列之后，实体内部消费处理逻辑，由实体自行实现，协议不做规定。
3. cc_crid 不存在 /cap_id 在 CC 内不存在时，biz_code 返回错误码，payload.data 置为 null。
4. Cap 存在，但该 Cap 下无任何动作项时，biz_code 返回 "0"，data.action_list 返回空数组 []，不视为业务错误。
5. 框架层校验规则沿用 call 元语通用约定：当 header.ret_code ≠ "0000" 时，biz_code /biz_msg 不可信，调用方禁止依赖。
