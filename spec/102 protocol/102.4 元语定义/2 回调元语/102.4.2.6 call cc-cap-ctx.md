### 102.4.2.6 call cc-cap-ctx

**元语签名**：call(destEp: Endpoint, path: "cc-cap-ctx", payload: CcCapCtxParams, ctrlMap?: CtrlMap) -> ResMsg

- destEp：目标端点，此处为**CC 实例对应的 Endpoint 对象**。


**描述**：call cc-cap-ctx（接口方法元语｜同步定向查询）。SV 调用 CC 暴露的接口，获取能力上下文，读取指定能力完整运行上下文，支撑 CDT 在 Cap 作用域内读取上下文信息，辅助推演决策。

> 类比 Vue 组件的 data：data 是能力实例的响应式状态容器。打开 Word 文档、拉起表单界面填写，文档内容、表单录入字段、界面交互状态全部收纳于此；内部字段由 Cap 自行定义，协议层不预设、不拆分内部属性。


**请求 payload**

```
{
  "cc_crid": "string",
  "cap_id": "string"
}
```

**Payload 字段说明（请求）**

- cc_crid：CC 实体 CRID，实体唯一标识。CRID 绑定独立事件队列；事件总线依靠该 CRID 定位目标 CC 实体对应的事件队列，完成本次调用消息投递。
- cap_id：Cap 在 CC 内部的局部标识；cc_crid + cap_id 联合构成全局唯一能力定位标识。

**响应 payload**

```
{
  "biz_code": "0",
  "biz_msg": "",
  "data": {}
}
```

**Payload 字段说明（响应）**

- biz_code：业务状态码，"0" 代表调用成功；非 0 代表业务异常。
- biz_msg：业务提示信息，成功时为空字符串，异常时存放错误描述文本。
- data：能力上下文容器，类比 Vue 组件 data。承载该能力实例全部响应式状态，内部字段、状态规则完全由对应 Capability 自主定义，协议不强制规定内部结构。

**约束**

1. 基于 cc_crid、cap_id 定位目标能力上下文。
2. data 类比 Vue 组件 data，为能力实例状态容器；内部结构、状态定义由对应 Capability 自行管控，协议层不预定义固定子字段。
3. CRID 为实体唯一标识，每一个 CRID 对应一条独立事件队列。进程内事件总线依据 CRID 定位目标事件队列，完成事件投递。UPP、CC、SE 为该体系下的实体，每个实体实例分配独立 CRID 与专属事件队列；SV 为壳式组件，不占用独立 CRID，注册所用 CRID 即 CDT 的 CRID。事件投递入队列之后，实体内部消费处理逻辑，由实体自行实现，协议不做规定。
4. cc_crid 不存在 /cap_id 在 CC 内不存在时，biz_code 返回错误码，payload.data 置为 null。
5. 框架层校验规则沿用 call 元语通用约定：当 header.ret_code ≠ "0000" 时，biz_code /biz_msg 不可信，调用方禁止依赖。
