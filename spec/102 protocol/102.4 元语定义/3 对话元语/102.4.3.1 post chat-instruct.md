### 102.4.3.1 post chat-instruct

**元语签名**：post (destEp: Endpoint, path: "chat-instruct", payload: ChatInstructParams, ctrlMap?: CtrlMap) -> ResMsg

- destEp：目标端点，此处为 CDT 实例对应的 Endpoint 对象。

**生产者**：SE 

**契约消费者**：CDT

**描述**：用户对话指令事件，一次用户业务操作的起始点，生成 chatId。ret_code 仅代表「消息是否成功投递至 CDT」，不是用户指令业务处理结果。

**请求 payload**
```
{
  "sessionId": "string",
  "conversationId": "string",
  "chatId": "string",
  "event_type": "chat_instruct",
  "user_input": "string"
}
```

**响应说明**：
```
{
  "ret_code": "string",
  "ret_msg": "string"
}
```

**约束**

1. 本元语为异步投递契约：on 就绪回执仅确认 CDT 收到消息、完成入队，不代表用户指令业务执行完成。业务执行结果通过后续 emit 事件元语推送。
2. ret_code 含义：
   - 0000：CDT 成功接收本条 chat_instruct 消息，已入队，开始异步处理。
   - 非 0 错误码：消息校验失败 / 存储失败，CDT 未接收，业务可选择重试。
3. chatId 为本条用户业务操作唯一标识，在本元语生成。
4. event_type 固定取值 chat_instruct，用于 CDT 识别事件类型。
5. sessionId、conversationId 为会话、对话层级独立标识，与 chatId 分属不同生命周期。
