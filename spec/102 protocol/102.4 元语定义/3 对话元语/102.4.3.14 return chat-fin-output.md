### 102.4.3.14 return chat-fin-output

**元语签名**：return(reqMsg: ReqMsg, payload: ChatFinOutputParams, ctrlMap?: CtrlMap) -> ResMsg

- reqMsg：原始请求消息实例，用于提取标识，生成本回调报文的 correlation_id

**生产者**：SV

**契约消费者**：SE

**描述**：return 为点对点异步推送元语。SV 模板格式化之后，给 SE 渲染展示给用户的最终输出事件；return 报文一旦发出，代表该 reqMsg 对应的业务处理生命周期结束，不再继续产生针对该 reqMsg 的后续推送报文，业务链路闭环。

**请求 payload（return 报文内 payload）**

```
{
  "biz_code": "0",
  "biz_msg": "",
  "data": {
    "sessionId": "string",
    "conversationId": "string",
    "chatId": "string",
    "event_type": "chat_fin_output",
    "display_final": "string"
  }
}
```

**本地构造返回报文（primitive="none"，内存构造，非远端网络回包）**

```
{
  "ret_code": "string",
  "ret_msg": "string"
}
```

**约束**

1. return 为点对点异步推送元语，元语层自动完成 meta、header 组包；src_crid、dest_crid 由元语层自动填充，业务侧无需传入。meta.primitive 固定为 "return"；本地构造返回报文 primitive="none"，仅用于 EventBus 入队确认、释放发送侧资源，业务代码不基于该报文执行业务逻辑。
2. biz_code = "0"：业务执行成功，biz_msg 可为空；biz_code ≠ "0"：业务执行失败，biz_msg 存放可读业务错误描述，接收方忽略 data 内容。
3. display_final：经 SV 模板格式化、面向用户可读的最终业务结果文本，供 SE 渲染展示。
4. event_type 固定取值 chat_fin_output。
5. 收到对应 correlation_id 的 return 报文后，该 correlation_id 后续 notify 报文全部丢弃。
6. 标志当前 chatId 任务业务链路闭环；不销毁 session、conversation 顶层上下文。
7. header.deadline 取自 ctrlMap 配置；ctrlMap 不传时 deadline 默认等于 0，表示无超时限制。接收方处理前校验 deadline，超时则直接丢弃本条 return 报文。
