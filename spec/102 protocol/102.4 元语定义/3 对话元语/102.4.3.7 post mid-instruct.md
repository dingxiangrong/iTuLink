# 102.4.3.7 post mid-instruct

**元语签名**：post (destEp: Endpoint, path: "chat-event", payload: MidInstructParams, ctrlMap?: CtrlMap) -> ResMsg

- destEp：目标端点，此处为 SE 实例对应的 Endpoint 对象。

**生产者**：CDT

**契约消费者**：CC

**描述**：推演中间阶段指令，阶段性机器指令，SE 执行中间指令。本条指令与 post fin-instruct 采用同一套寻址与执行模型：可直接执行无状态能力单元，或对有状态能力调用能力本体拉起实例、实例就绪后执行业务 action；仅承载阶段性指令，不代表请求处理完毕；请求处理完成的标记由 return 报文承载。

**请求 payload**

```
{
  "sessionId": "string",
  "conversationId": "string",
  "chatId": "string",
  "event_type": "mid_instruct",
  "cc_crid": "string",
  "cap_id": "string",
  "action_id": "string",
  "action_param": {}
}
```

**响应说明**

```
{
  "ret_code": "string",
  "ret_msg": "string"
}
```

**约束**

1. 本元语为异步投递契约，就绪回执仅确认 SE 收到中间指令并完成入队；指令执行完成的业务结果，由后续 emit 事件推送。
2. ret_code="0000"：SE 成功接收中间指令；非 0 代表投递 / 校验失败，SV 可重试下发。
3. 依靠 `cc_crid + cap_id` 定位目标能力单元。`action_id` 为可选字段：不携带`action_id`代表直接调用能力单元，参数放置于`action_param`，参数定义引用 §103.4.4。对于`stateMode=Stateful`的有状态能力，由能力自身解析`action_param`，自主判断为新建实例或是加载外部持久对象，目标实例不局限于当前 chat 任务上下文；携带`action_id`代表在已就绪的有状态能力实例上，执行该能力下属 action，action_id 取自能力定义的 action 集合。本元语一次仅传递单条指令；多条中间指令场景，SV 多次独立发送本元语。本条寻址、执行模型与 post fin-instruct 保持一致。
4. event_type 固定取值 mid_instruct。
5. 本指令属于 chatId 任务的中间环节；不销毁 session、conversation，仅作用于当前 chatId 任务链路。
