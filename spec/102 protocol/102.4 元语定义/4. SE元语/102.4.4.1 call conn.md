### 102.4.4.1 call conn

**元语签名**：call(destEp: Endpoint, path: "conn", payload: ConnParams, ctrlMap?: CtrlMap) -> ResMsg

- destEp：目标端点，此处为 SV 实例对应的 Endpoint 对象。

**描述**：call conn（接口方法元语｜同步定向调用）。SE 主权入口主动向 SV 执行 call conn。仅用于完成 SE 主权入口与 SV 的底层通信通路握手建立，连接成功返回通路凭证，不承载上层业务会话逻辑。

**请求 payload**

```
{
  "se_id": "string",
  "se_instance_id": "string",
  "sv_instance_id": "string",
  "link_key": "string"
}
```

**响应 payload**
```
{
  "biz_code": "0",
  "biz_msg": "",
  "data": {
    "conn_id": "string"
  }
}
```

**Payload 字段说明（响应）**
biz_code：业务状态码，"0" 代表调用成功；非 0 代表业务异常。
biz_msg：业务提示信息，成功时为空字符串，异常时存放错误描述文本。
data：通信通路元数据对象。
conn_id：SE-SV 通信通路的唯一凭证。

**约束**

1. se_id：主权入口全局唯一标识。
2. se_instance_id：主权入口实例唯一标识。
3. sv_instance_id：目标 SV 实例唯一标识。
4. link_key：链路密钥，用于通路可信核验，不携带上层用户身份信息；link_key 可在首次配对协商生成，后续重连复用，类似蓝牙配对链路密钥；链路密钥仅用于实例间通道可信，和上层 UPP 用户身份体系完全解耦。
5. conn 完整参数结构以模块文档定义为准，上文仅作逻辑参数占位。
6. 全部连接动作采用 call conn 接口元语调用，请求携带链路密钥用于通路核验。每一次 call conn 调用仅返回成功或者失败，仅用来确认单条通信通路是否建立。CONN 执行结束即本流程完结。会话、能力切换等全部业务逻辑，交由角色内部完成，本阶段不运行业务流程。
7. SE 作为主权入口，仅负责前端交互入口；账号、登录、权限等身份授权统一由 UPP 承载。CONN 只解决通信通路，依靠链路密钥完成链路层面核验；登录核验、身份确权属于 UPP 业务，会话鉴权属于 CC 业务，在 CONN 通路就绪之后再执行，不在 CONN 流程之内。
8. 本设计遵循 101 总体架构公理 4：端侧自治域拥有最终否决权，角色内部业务不受外部强制驱动。
9.【预留扩展】CONN 的应答字段、连接失败处理、链路心跳，后续专项补充，本章只定义顶层连接关系。
9. 框架层校验规则沿用 call 元语通用约定：当 header.ret_code ≠ "0000" 时，biz_code /biz_msg 不可信，调用方禁止依赖。
