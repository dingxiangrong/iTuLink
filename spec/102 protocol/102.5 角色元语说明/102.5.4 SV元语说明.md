## 102.5.4 SV事件流

### 一、初始化 / 接收绑定

1. **on bind**（UPP 调用）

- 调用发起方：UPP
- 处理：接收 UPP 绑定

2. **on conn**（SE 调用）

- 调用发起方：SE
- 处理：接收 SE 连接绑定

### 二、主动一级事件：能力空间查询接口组

**触发条件**：会话初始化、能力状态刷新、路由合法性校验、对话调度前置校验场景，主动触发调用
**处理方式**：按需发起只读查询，缓存全量元数据、能力列表、上下文信息，用于后续所有事件的路由合法性校验、权限校验、能力可用性校验；upp 相关查询目标为外部宿主 UPP

**二级 Post 事件（逐条）**

1. `post upp-meta-get` → 【外部宿主 UPP】：刷新会话元数据
2. `post upp-cc-enum` → 【外部宿主 UPP】：刷新容器挂载列表
3. `post cc-meta-get` → CC：刷新容器基础信息
4. `post cc-cap-enum` → CC：刷新容器能力清单
5. `post cc-cap-desc` → CC：刷新目标能力详细配置
6. `post cc-cap-ctx` → CC：刷新能力运行上下文

### 三、状态事件（接收）

- `on session-event (session-in)`
- `on session-event (session-out)`
- `on focus-event (focus-in)`
- `on focus-event (focus-out)`

### 四、对话事件

1. **on chat-event (chat_instruct)**

- 触发条件：SE 发起用户对话指令，SV 本地缓存存在有效会话实例（数据源头外部宿主 UPP）
- 处理：优先校验当前会话合法性、CC 能力激活状态；为确保调度精准，主动获取当前活跃能力实时运行上下文，完成前置校验后转发对话指令
- 二级 Post 事件：`post cc-cap-ctx` → CC（查询当前聚焦活跃能力的实时运行上下文、历史对话状态、参数缓存、执行进度，校验能力是否可承接本轮对话任务）
- 后置路由：会话、能力状态、上下文校验全部通过后，`forward chat_instruct` → CDT 代理层

2. **on chat-event (chat_cancel)**

- 触发条件：SE 下发用户任务终止指令，存在活跃对话任务
- 处理：校验当前会话有效性，确认待终止任务 ID，透传终止信号至推演代理层与能力执行层，终止本轮未完成任务
- 二级响应：`forward chat_cancel` → CDT 代理层、`forward chat_cancel` → CC

3. **on chat-event (alert)**

- 触发条件：CDT 代理层抛出风险告警事件
- 处理：校验会话与链路状态合法，无状态变更，原样透传告警事件至前端
- 二级响应：`forward alert` → SE

4. **on chat-event (choice)**

- 触发条件：CDT 代理层抛出冲突选择事件
- 处理：校验会话与链路状态合法，原样透传选择交互事件至前端
- 二级响应：`forward choice` → SE

5. **on chat-event (alert_ack)**

- 触发条件：SE 返回用户告警确认回执
- 处理：校验会话合法性，透传用户确认回执至推演代理层，解除风险阻塞状态
- 二级响应：`forward alert_ack` → CDT 代理层

6. **on chat-event (choose)**

- 触发条件：SE 返回用户选择决策结果回执
- 处理：校验会话合法性，透传用户决策数据至推演代理层，推进分支逻辑执行
- 二级响应：`forward choose` → CDT 代理层

7. **on chat-event (chat_stream)**

- 触发条件：CDT 代理层推送对话流式分片数据
- 处理：无数据篡改、无状态变更，原样透传流式分片至前端，保障实时输出
- 二级响应：`forward chat_stream` → SE

8. **on chat-event (mid_instruct)**

- 触发条件：CDT 代理层下发中间推演机器指令
- 处理：校验指令合法性与会话状态，透传原始执行指令至能力层，同时封装用户可读通知事件推送前端
- 二级响应：`forward mid_instruct` → CC；`emit chat_mid_instruct`

9. **on chat-event (mid_output)**

- 触发条件：CC 返回能力中间执行结果
- 处理：透传中间执行结果至推演代理层用于后续逻辑迭代，同时封装前端展示事件，推送中间结果至用户界面
- 二级响应：`forward mid_output` → CDT 代理层；`emit chat_mid_output` → SE

10. **on chat-event (fin_instruct)**

- 触发条件：CDT 代理层下发本轮收尾终结机器指令
- 处理：透传收尾执行指令至能力层，同时推送收尾任务通知至前端，提示用户任务即将完成
- 二级响应：`forward fin_instruct` → CC；`emit chat_fin_instruct` → SE

11. **on chat-event (fin_output)**

- 触发条件：CC 返回本轮对话最终执行结果
- 处理：标准化格式化最终输出数据，根据系统配置决定是否备份结果至 CDT 代理层，最终推送完整结果至前端
- 二级响应：可配置 `forward` 副本至 CDT 代理层；固定 `emit chat_fin_output` → SE

## 汇总

- 接收绑定：on bind（UPP）、on conn（SE）
- 主动查询：upp-meta-get、upp-cc-enum、cc-meta-get、cc-cap-enum、cc-cap-desc、cc-cap-ctx
- 接收状态事件：session-in/session-out、focus-in/focus-out
- 对话事件处理：chat_instruct /chat_cancel/alert /choice/alert_ack /choose/chat_stream /mid_instruct/mid_output /fin_instruct/fin_output
- 关键动作：校验 + 透传（forward）+ 封装（emit 用户可读事件）
