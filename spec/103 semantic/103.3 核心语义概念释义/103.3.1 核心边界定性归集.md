### 103.3.1 核心边界定性归集

本节仅做定性归类、边界区分，不扩展时序逻辑、不涉及调度推演细节。  

**核心结论**：CAP 内部状态机跃迁、状态树切换，并非业务数据模型、底层数据库强制分步要求；本质是交互界面 / 操作环境带来的能力约束，属于界面约束下两类典型特例。业务层约束和界面层约束相互独立，不可混为一谈。  

严格边界区分如下：

1. 主数据关联录入（业务模型固有约束）  
属于业务数据模型底层刚性约束，和界面无关。底层存储只识别唯一编码，不识别文本名称。无论前端界面操作，或是后台无界面 API 调用，都必须完成「文本名称→系统编码」映射转换。这是业务数据合法性的固有要求，不属于界面约束。

2. 状态机跃迁 / PS 模式切换（界面环境约束特例）  
属于人机交互界面环境约束。系统工具锚点、操作权限依赖指定运行模式，必须切换模式之后才可执行操作；该分步约束来自界面交互形态，不是业务数据本身的强制要求。

3. 状态树切换 / 设备多级视图（界面环境约束特例）  
典型场景为网络设备 CLI 分层视图，必须逐层进入视图才能执行对应指令。约束来自设备交互界面层级限制，业务数据本身不存在强制分步逻辑。

4. 界面分步导航 Step 流程（纯 UI 交互约束）  
前端表单分页、分步提交等交互形态，仅用于 UI 体验引导，不修改底层业务数据结构与业务规则。
