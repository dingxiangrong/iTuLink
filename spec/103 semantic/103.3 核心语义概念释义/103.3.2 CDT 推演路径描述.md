### 103.3.2 CDT 推演路径描述

#### 3.2.1 推演数据源

CDT 推演输入：

1. 当前 CAP 全部 Action 定义；

2. 每个 Action 的 dependsActions 候选前置依赖模板；

3. 用户输入 / 会话上下文（用于命中目标、实例化参数、取舍候选依赖）。

#### 3.2.2 推演规则

1. CDT 获取 Cap 的所有 Action；

2. Action 携带静态声明的候选前置依赖模板 dependsActions；

3. CDT 接收用户输入，通过 synonyms 匹配 / 意图解析，首次识别命中的目标 Action—— 仅目标 Action 由用户输入直接命中；被依赖的 Action 无法仅凭用户输入识别；

4. CDT 以目标 Action 的 dependsActions 为候选模板，结合用户输入上下文动态推演实际依赖（实例数量、取舍），追加为目标 Action 的实际 depend_list；

5. 对每个实际依赖项递归解析其自身 dependsActions，逐层向下展开，形成实际依赖闭包 / 依赖树；

6. 按依赖层次调度执行：同层平行依赖项无顺序要求，可并行或按调度策略执行；深层依赖必须先于其直接后继满足；

7. 依赖闭包全部满足后，执行目标 Action；

8. 目标 Action 完成后输出指令判定：存在未执行的后续节点 → post mid_instruct 压栈继续；依赖闭包已终结（无后续节点）→ post fin_instruct。

#### 3.2.3 Action 平等性与识别边界

1. 所有 Action 地位平等，均为 CAP 对外暴露的可调度单元，无主路径 / 旁路之分。取消、缓存、提交等 Action 同样携带 dependsActions 参与拓扑；是否进入本轮实际 depend_list，取决于用户输入是否命中及其依赖链是否被展开。

2. 用户输入仅三项作用：命中目标 Action（synonyms / 意图解析）；提供实例化参数；决定候选依赖取舍（本轮需要 / 跳过）。

3. 被依赖的 Action 对用户透明、对 CDT 可见：被依赖 Action 由 CDT 基于 dependsActions 递归推演自动展开，用户无需感知也通常无法感知。如用户只说 “填报商机”，客户 / 产品检索由 CDT 展开，用户不会说、也不需要说 “先查客户字典”。

#### 3.2.4 指令语义

1. mid_instruct：当前推演链未终结，CDT 继续自动调度；

2. fin_instruct：本轮推演链闭环结束。

#### 3.2.5 防环约束

递归展开时，若某 Action 已出现在当前展开路径 / 依赖闭包中，构成循环依赖；CDT 报错终止，不进入执行。

**概念区分**

| 术语                                           | 含义                            |
| -------------------------------------------- | ----------------------------- |
| dependsActions                               | 静态声明的候选前置依赖模板（CAP 静态定义，类型级）   |
| actual depend_list / resolved depend closure | 基于用户输入动态推演实例化后的实际依赖结构（推演过程产物） |
| 拓扑 / DAG                                     | 整体 CAP 依赖结构约束（底层结构）           |
| 递归展开                                         | CDT 针对当前目标 Action 的解析 / 调度视图  |

> **关系说明**：DAG 是底层结构约束；CDT 推演时以目标 Action 为根展开为依赖树（依赖闭包）处理，而非简单 DAG 入度队列平铺。
