### 103.4.5 动作项（Action）

**继承**：语义主体（SemanticSubject）  
可被触发的最小语义执行点位。

| 字段名            | 类型               | 是否必选 | 说明                                                                                                                                                                               |
| -------------- | ---------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| input          | InputParamSpec[] | 可选   | 平行输入参数集合，空数组代表无输入                                                                                                                                                                |
| output         | OutputSpec｜null  | 可选   | 顶层输出封装结构，null 代表无输出                                                                                                                                                              |
| dependsActions | ActionRef[]      | 可选   | 静态候选前置依赖模板集合，声明本 Action 执行前需要满足的前置动作项集合。CDT 在推演阶段结合会话上下文实例化，生成实际 depend_list。ActionRef 为动作项引用类型，至少包含 targetActionId，该引用结构由下游实现层定义。                                               |
| synonyms       | string[]         | 可选   | 语义目标标签集合。1. 意图解析：用户输入命中 name 或任意词条，匹配本动作项；2. 试错纠偏：本动作项执行失败时，CDT 使用本组标签，全局查找拥有任意一个重叠词条的其它动作项，动态生成等价备选候选池； 候选池排序、过滤、重试控制由下游 CDT 实现层负责；本元模型仅存储标签，不维护硬对象引用；支持单个实体携带多组目标词条，天然兼容多语义场景。 |

**语义约束：**

1. dependsActions 仅用于静态模板声明，实际依赖实例、执行顺序由 CDT 基于 dependsActions 递归推演生成实际依赖闭包（依赖树）决定，底层 DAG 仅作为静态结构约束。

2. 所有 Action 地位平等，无主 / 旁路区分；是否进入本轮实际 depend_list，由目标 Action 命中结果与依赖链展开共同决定。

3. 推演流终止判定交由 CDT 依赖闭包统一判定：依赖闭包无后续待执行节点时输出fin_instruct；存在未执行后续节点则输出mid_instruct。

4. 推演流终止仅代表结束本轮 CDT 发起的自主执行流，不代表 CAP 业务实例销毁；CAP 实例仍可留存，可再次发起新一轮自主执行。
